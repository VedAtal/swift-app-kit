# App standards

Every app built on swift-app-kit follows these rules, so the apps look, install, and behave the
same way. Where the kit can enforce a rule, it does, and this file says so.

## Repo

- Each app has its own **public** GitHub repo. It has to be public because updates download over
  HTTPS without credentials.
- Layout: `Package.swift`, `Package.resolved` (committed), `app.env`, `setup.sh`, `README.md`,
  `.gitignore`, `Sources/<App>/`. App-specific scripts go in `scripts/`.
- `setup.sh` is an unchanged copy of `templates/setup.sh`. Anything app-specific goes in `app.env`.
- `BUNDLE_ID` is `local.<lowercase name>`. Never change it after the app is installed: macOS
  keys settings and permissions to it.
- Commit messages are short and lowercase: `init`, `use github as source`, `fix paste delay`.

## Menu bar

Enforced by `MenuBarAppDelegate`. The app adds only the top section:

```
<app items>                    the app's own commands and status
───────────
Grant Accessibility Access…    only while it's needed and missing
Launch at Login                checkmark
Settings…                ⌘,
───────────
Update <App>
Version 59ba24f · built 2 minutes ago
Quit <App>               ⌘Q
```

- The menu bar icon is the app's `SYMBOL` (or `GLYPH`), drawn as a template image so it matches the
  menu bar.
- Menu items that have a shortcut show it on the right (`menu.addItem(_:shortcut:action:)`).
- Status lines (e.g. "Open history: ⇧⌘V") are disabled items in the app's section.
- Use title case for commands ("Clear History", "Pause Snap") and "…" for items that open a
  window or ask something more.

## Settings window

Enforced by `SettingsForm`:

- A grouped `Form`, 500 points wide. The app's sections come first, then **General** (launch at
  login, and Accessibility status if the app needs it).
- Section headers are short nouns ("Shortcut", "History"). Put explanations in section footers,
  in secondary text.
- Shortcuts are always set with `ShortcutField`.
- Opening the app again from Spotlight or Finder opens Settings.

## Shortcuts

- Global shortcuts need ⌘, ⌃, or ⌥ (`Shortcut(event:)` enforces this).
- Prefer **⌃⌥** for sets of global shortcuts. ⌘⌥ clashes with tab switching in browsers and
  editors, and ⌘⌥D shows or hides the Dock everywhere.
- Register them with `HotKeyCenter` under a stable name, and pass that name to `ShortcutField`,
  so conflicts show in Settings.
- Every shortcut can be changed in Settings.

## Icon

Generated by `scripts/make-icon.swift` from `app.env`: a white SF Symbol on a rounded square
(Apple's macOS icon grid) with a top-to-bottom gradient. Each app picks its own symbol and
gradient. Keep both colors in the same hue family, and keep them saturated enough for white to
read on top.

An app with its own mark sets `GLYPH` to a PNG in its repo, cropped to the shape. It replaces the
symbol in both the app icon (drawn white) and the menu bar (a template image, so it follows the
menu bar's light or dark appearance). Only its alpha is used, so one image covers both.

| App | Symbol | Gradient |
|---|---|---|
| Recall | `list.clipboard` | blue → purple |
| Snap | `rectangle.split.2x2` | green → teal blue |
| Cairn | its own glyph (stacked stones) | graphite → black |

## Code

- Swift 6, macOS 14+, builds with only the Command Line Tools.
- **No `@State` or `@StateObject`.** Their macro plugin only comes with full Xcode. Keep view
  state in `ObservableObject` classes and use `@ObservedObject`.
- Settings go in a `Preferences` class: a `shared` instance with `@Published` properties
  saved to UserDefaults. AppDelegate subscribes to changes and applies them right away.
- Data lives in `~/Library/Application Support/<App>`, logs in `~/Library/Logs/<App>`.
  `setup.sh --uninstall` removes both, along with UserDefaults, the login item, the
  Accessibility entry, and the signing keychain.

## README

Each app's README uses these sections, in this order:

1. **Title and one or two sentences** saying what it does.
2. **Setup**: the one command (`curl -fsSL …/swift-app-kit/main/scripts/install.sh | bash -s <app>`),
   what it does, the options table, and the one manual step if there is one (usually Accessibility).
3. **Updating**: the menu item, `./setup.sh`, and `./setup.sh --local`.
4. **Using it**: a table of what to press and what it does, then the menu.
5. **Settings**.
6. **Uninstall**.
7. **Troubleshooting**.
8. **How it works**: a file map of `Sources/<App>/` and the details that aren't obvious.
   Link to swift-app-kit for the shared parts instead of explaining them again.
9. **Development**.
